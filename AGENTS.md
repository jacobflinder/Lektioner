# Publishing lesson changes

## The teacher's mathematical norm is binding (all lessons)

- **The teacher's original lesson is the authority for mathematical content, notation, worked-solution order and calculation method.** The task is to improve how pupils learn *that* lesson, never to replace its mathematics with another convention or introduce a new topic because a generic teaching model recommends it. Read the original PDF/film/transcript and create a source-to-web content checklist before writing. Correct demonstrable mathematical errors transparently; do not silently substitute a different method.
- **Mandatory source-to-lesson fidelity gate for Fy2, Fy1/Fy N1b, Ma4 and Ma3c/mato1c:** Before implementation, map each original definition, theorem, concept, representation, worked-solution method and critical intermediate step, sign/notation convention, example type, lab, Socrative segment and other student activity to its intended location in the new web lesson. Mark each item `preserved`, `didactically improved` or `proposed deviation`. Check the final web lesson against this map and include the outcome in the completion report. Any missing source item, unexplained methodological substitution or unapproved deviation from the teacher's substantive mathematics/physics **blocks a “finished” report and publication**, regardless of passing code tests. If source materials are missing, say so and obtain them instead of claiming fidelity.
- **Teach the teacher's method in the teacher's order.** Introduce a central theorem, definition or symbol visibly *before* its first use in a worked calculation; never first reveal it inside a solution step. Preserve complete algebraic substitution chains, with each critical line readable together, and the teacher's conventional notation (for definite integrals, for instance, `∫_a^b f(x) dx = [F(x)]_a^b = F(b) − F(a)` if this is the teacher's method). Do not replace a direct mathematical calculation with an extensive exploratory detour, even if an initial geometric/experimental progression is valuable. Avoid unnecessary vocabulary about notation, and preserve subject-specific physical conventions equally carefully.
- Keep every mathematical idea, explanation and relevant example type from the original, adapting numerical examples and book exercise numbers when the user asks not to copy the textbook. Preserve the teacher's way of evaluating integrals, including the bracket notation, `F(b)-F(a)` and the complete substitution chain. Add visualizations, questions and feedback to clarify that method, not to displace it.
- **Do not add signed/negative-area integrals, extra rules, exceptions or other mathematical content** unless the teacher includes them in the original lesson or explicitly requests them. Previously added extras that do not pass this test must be removed when that lesson is revised. Retain explicitly requested labs and Socrative activities.
- **Socrative in every lesson (teacher decision 2026-11-26):** Whenever an original Socrative activity is used, show pupils its entire, unabbreviated original activity name, including its number, and the exact full `SOC-...` identifier. Do not shorten it to “Soc”, a topic, or only a number. Verify the title and code against the teacher's source; never invent a Socrative activity or code.
- **Thinking before mathematical answers in every lesson (teacher decision 2026-11-26):** Show the problem and its relevant diagram before the mathematical response. Give pupils an explicit chance to predict, formulate or calculate on paper before showing the requested mathematical steps or result, including results embedded in diagram labels. Reveal a complete, readable solution chain **on the same slide as the diagram** on deliberate action. A new foundational definition or theorem must still be introduced in full before its first application; do not replace the teacher's calculation with a guessing game.
- **Length cap:** aim for **8–10 main slides** per lesson and **about 10–13 slides in total including clearly optional extras**, whenever pedagogically and mathematically feasible. Do not use the cap to omit a necessary original calculation or a complete book assignment. When an exception is truly necessary, explain why before extending the lesson.
- Start with **three concrete, observable learning goals** connected to a later individual check, unless the teacher has explicitly decided on a different course-specific format. Respect every course's own didactic source, book pagination, level rules, homework and weekly rhythm. In Ma3c, “at least two of three levels” means **all tasks on at least two complete levels**, not a few tasks cherry-picked from each.
- Distinguish the main teaching path from optional enrichment; optional content must never interrupt access to Socrative, book work, homework and exit feedback. Confirm explicitly that the final lesson follows the source before declaring it ready.
- **Fy1 / Fy N1b textbook exercises are mandatory when assigned (teacher decision, 2026-11-23):** If the teacher specifies an exercise interval or an explicit list, **every assigned exercise must be completed**. Prioritizing the order of work is not permission to make later, harder or multi-part exercises optional. Never label an assigned exercise “if you have time”, “optional enrichment”, or equivalent unless the teacher explicitly authorizes that exception. Work unfinished during the lesson must be finished as homework unless the teacher directs otherwise. Identify an exercise already completed in a worked classroom example so it is not assigned again unnecessarily. Optional *scaffolding* for a required exercise is allowed; the exercise itself remains required.
- **For Fy1 / Fy N1b bookwork slides:** Show a clear practical assignment and order (“start with”, “then do”, “finish the rest at home”), not a distracting goal-classification matrix. If the teacher wants the textbook exercises mapped to learning goals, display those connections concisely *under each goal on the exit/goal review slide*, not in place of the work instructions. Preserve accurate page and task numbers from the current textbook and all originally assigned work. Verify both the work instruction and the exit mapping against the teacher's decision before publication.

- **Self-contained classroom execution (Fy1/Fy N1b and subsequent web lessons, teacher decision 2026-11-23):** The main classroom lesson must itself communicate *every action needed to teach the original*: start question, teacher-led demonstration or experiment with essential setup/actions and when to perform it, video or simulation with an exact verified link where used, mindmap/board-work and what pupils add, individual→pair→class instructions, calculation/reveal order, bookwork, homework and exit. A teacher must be able to deliver the lesson from its visible classroom slides **without opening teacher notes or a separate teacher-guide page**. Supplementary teacher notes may hold background, provenance and optional advice only; they may never be the sole location of a source-required demo, experiment, video, activity or assignment. Never add demos, videos, Socrative or labs unless grounded in the original or explicitly approved. Keep media marked “next lesson” out of the current lesson's activities; place them in the correct future lesson. In final QA, inspect the default classroom mode end-to-end for missing instructions and excessive teacher-facing metadata.
- **Later teacher decision, Fy N1b 9.3 and corresponding web-first lessons (2026-11-23):** The interactive web lesson REPLACES the former separate class mindmap. Preserve every substantive concept and the teacher's sequence from the old mindmap, but DO NOT tell pupils to create, copy or complete a parallel mindmap unless the teacher explicitly reinstates that activity. Likewise, an interactive diagram must never be the first introduction of its underlying theory or conventions: explain the quantities, axes/levels, arrows, transitions and relevant rule on a visible student slide BEFORE inviting clicks. For a nucleus energy-level diagram, teach ground/excited levels and gamma emission plus ΔW=W_before−W_after and E_gamma=ΔW before selecting transitions. Verify this actual order in QA.

- Prepare and test a complete logical change before publishing to main.
- Commit lesson changes and their corresponding browser tests together in one atomic commit. Do not publish intermediate single-file versions to main.
- Run the relevant browser QA commands from .github/workflows before publishing. If local execution is unavailable, use a working branch and validate it before merging to main.
- Preserve meaningful assertions: investigate failed tests and fix the lesson or update outdated interaction steps; never disable tests or hide failures just to obtain a green result.
- Read the latest branch head before publishing and preserve concurrent work by other chats. Never force-push over another change.
- Verify the final GitHub Actions result and Pages deployment before reporting success. Distinguish pending checks from passed checks.
- mato1c/ contains Ma3c / Matematik – fortsättning nivå 1c, not Matematik 1c. Keep these courses distinct.
- Visually separate independent equations, given values, and mathematical statements. Never put two complete equations (for example `u = 1 − 3i` and `z = −3 + 2i`) into the same `.math` element or rely on `&nbsp;`/plain spaces: the MathML formatter may collapse them into an ambiguous string. Use separate semantic math blocks; in Ma4 use `.math-givens` with at least 16px vertical spacing. Validate actual rendered distance at desktop and 390px mobile widths and inspect screenshots before considering a lesson reviewed.
- For every electrical circuit SVG, verify **actual conductor-to-terminal contact** in rendered geometry: wire endpoints must meet both battery plates and component terminals, not merely come close; no opaque masking shape may hide a required junction. Verify no unintended short-circuit or bypass path. Add a browser geometry regression across mobile/tablet/desktop/projector sizes and inspect the rendered figure before approval. Element presence and green functional tests alone are insufficient.
